# 0.6.1 — 2026-08-06

## Added

- **`publishingCountry`, `stateProvince`** — new filters on `gbif_search_occurrences`, `gbif_count_occurrences`, and `gbif_occurrence_facets`, closing the gap where `PUBLISHING_COUNTRY` and `STATE_PROVINCE` facet buckets had no matching filter to drill into. `publishingCountry` carries a `^[A-Z]{2}$` Zod pattern — GBIF answers a lowercase or alpha-3 code with 200 and zero records rather than rejecting it, so the pattern turns that silent case into a local validation error. `stateProvince` has no controlled vocabulary; a new `stateProvinceNoMatchNotice` (`src/mcp-server/tools/utils.ts`) fires on an empty result under it, naming the verbatim, case-sensitive match and pointing at a `STATE_PROVINCE` facet for exact values. ([#49](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/49))

## Changed

- **`pagination_cap_exceeded` recovery, the `gbif_occurrence_facets` `facet` description, and `createApp({ instructions })`** now name the two real complete-retrieval routes outside this server — GBIF's account-gated Download API and the AWS Open Data Parquet snapshot — and document `DATASET_KEY` as the one facet dimension whose buckets partition a result set with no gap or overlap, in place of pointing callers at `gbif_occurrence_facets` as if an aggregate count substituted for record retrieval. `BASIS_OF_RECORD` and `publishingCountry` are named as gap-free second-cut dimensions for a bucket still over the cap; `YEAR`, `MONTH`, `STATE_PROVINCE`, and `SPECIES_KEY` are named as dimensions that silently drop records missing the field. A new `overPaginationCapNotice` (`src/mcp-server/tools/utils.ts`) fires on `gbif_search_occurrences` and `gbif_count_occurrences` as soon as a total passes the 100,001 pagination cap, rather than only after a caller pages into the wall. ([#33](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/33))
- **Occurrence-corpus figure** corrected from 2.4B+ to 3.9B+ across tool descriptions, `README.md`, `docs/idea.md`, and `docs/design.md` — the prior figure was stale. ([#33](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/33))
