# 0.6.0 — 2026-08-06

## Added

- **`occurrenceStatus`** — output field on `gbif_get_occurrence` and `gbif_search_occurrences`; input filter (`PRESENT`/`ABSENT`/`ANY`) on `gbif_search_occurrences`, `gbif_count_occurrences`, and `gbif_occurrence_facets`; `OCCURRENCE_STATUS` added to the `gbif_occurrence_facets` dimension enum. Every query tool reports the applied value via `enrichment.occurrenceStatus` plus a notice naming the opt-out. ([#36](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/36))
- **`iucnRedListCategory`** — output field on `gbif_get_occurrence` and `gbif_search_occurrences`; input filter (closed nine-value enum: `CR`, `EN`, `VU`, `NT`, `LC`, `DD`, `EX`, `EW`, `CD` — `NE` excluded, it matches zero records) on the three occurrence query tools; `IUCN_RED_LIST_CATEGORY` added to the facet dimension enum. ([#37](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/37))
- **`taxonomicStatus`, `eventTime`** — output fields on `gbif_get_occurrence` and `gbif_search_occurrences`, rendered in `format()` and `structuredContent`. `eventTime` carries the UTC offset and seconds `eventDate` omits, not a fallback for a missing time. ([#44](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/44))
- **`gadm.level3`** — fourth GADM level (municipality/ward) added to `RawGadm`, `compactGadm`, and the `gbif_get_occurrence` output/`format()` chain, extending the levels 0–2 support from [#27](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/27). ([#44](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/44))

## Changed

- **`gbif_count_occurrences`** now reads its total from `/occurrence/search?limit=0` instead of `/occurrence/count`, which rejects `occurrenceStatus` and `iucnRedListCategory` with `Invalid parameter name`. `isGeoreferenced` maps internally to the search endpoint's `hasCoordinate` — the input name is unchanged. ([#36](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/36))
- **`recordCount`** descriptions on `gbif_get_dataset`, `gbif_search_datasets`, and the `gbif://dataset/{datasetKey}` resource now state the figure spans every `occurrenceStatus`, absences included, and name `gbif_count_occurrences` as the presence-scoped alternative; both dataset tools also render the scope inline in `format()`. `gbif_count_occurrences`'s `datasetKey` description says the same from the other side. Server `instructions` note the same gap. ([#48](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/48))

## Fixed

- **`gbif_search_occurrences`, `gbif_count_occurrences`, `gbif_occurrence_facets`** now default `occurrenceStatus` to `PRESENT`, excluding absence records — documented surveys that looked for a taxon and did not find it — that were previously counted and returned unlabelled alongside sightings. On absence-heavy taxa this changes results by orders of magnitude (2,351,582 → 79 for one reported case). Pass `occurrenceStatus: "ANY"` to restore the prior unfiltered total. ([#36](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/36))
- **`resolveDatasetRecordCount`** no longer gates its supplementary lookup on `type === 'OCCURRENCE'` — `/dataset/search` reports `recordCount` for all four dataset types, so `gbif_get_dataset` and the `gbif://dataset/{datasetKey}` resource previously returned no `recordCount` at all for non-`OCCURRENCE` datasets (e.g. `SAMPLING_EVENT`) that `gbif_search_datasets` counted correctly. ([#48](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/48))
