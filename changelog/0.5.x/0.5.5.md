# 0.5.5 — 2026-08-06

## Fixed

- **`gbif_match_species`, `gbif_bulk_match_species`** — `taxonKey` now resolves to the accepted backbone taxon (`acceptedUsageKey ?? usageKey`); the previously-returned synonym key is surfaced separately as `matchedTaxonKey` when it differs. `RawSpeciesMatch` gains `acceptedUsageKey`. Filtering the occurrence tools on a synonym's own key previously undercounted sharply — 106 records vs 18,961 for *Felis leo*. `gbif_match_species` emits an `enrichment.notice` naming both keys on a resolved synonym; `gbif_bulk_match_species`'s per-name catch now carries the thrown `McpError`'s `reason` onto the `ERROR` entry instead of flattening to a message only. ([#35](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/35))
- **`gbif_search_species`, `gbif_get_species_children`** `format()` — render `canonicalName ?? scientificName ?? 'Unknown'` instead of `canonicalName ?? 'Unknown'`, so a backbone entry with an unparseable binomial (no `canonicalName`) still prints its `scientificName` rather than "Unknown". ([#39](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/39))
- **`gbif_occurrence_facets`** `format()` — the `**Top N values:**` header, which misstated rank whenever `facetOffset` was nonzero, is replaced by a header naming the page's position in the ranking (or "No facet values in this page" when empty). ([#39](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/39))
- **`gbif_get_species_children`** — the truncation notice's `guidance` now names the offset to advance to and the limit ceiling, replacing the framework default's advice to narrow with filters; `/species/{key}/children` accepts no narrowing parameter (a `rank` value is ignored outright). ([#46](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/46))
- **`gbif_get_species_classification`** — gains an `enrichment.notice`, emitted when a taxon sits at the root of the backbone, stating the chain is empty because there are no parent ranks rather than because the lookup found nothing. ([#46](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/46))
- **`gbif_get_species`, `gbif_get_species_children`, `gbif_get_species_classification`, `gbif_get_occurrence`, `gbif_search_publishers`, `gbif://species/{taxonKey}`** — declare the `invalid_filter` reason each already threw for an unparseable key or country value, so it now appears in the `errors[]` contract read from `tools/list`. The two match tools are deliberately excluded: `/species/match` returns HTTP 200 for every input their schemas can produce. ([#47](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/47))
- **`MatchType`** — `HIGHERORDER` corrected to `HIGHERRANK`, the value GBIF's `/species/match` actually returns.
